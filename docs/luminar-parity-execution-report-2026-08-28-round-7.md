# Luminar Neo 1.28 对齐执行报告（第七轮，2026-08-28）

> 目标基线：本机 Luminar Neo 1.28.0 build 23071、zh-Hans。结论遵循 fail-closed：浏览器可用、模型可运行和单元测试通过都不能替代 Luminar 原生像素、交互与效果门禁。

## 1. 本轮结论

本轮完成了用户补充的目录、编辑器、预设、图层、裁切、右键菜单、更多工具和影像资讯的实现与浏览器实测，并删除了升级/帮助弹窗兼容路径。工程回归全部通过，但产品仍不能声明与 Luminar Neo 绝对一致。

功能级 required 门禁已经清零，但“绝对对齐”仍有两类 exact 阻断：

1. 92 个逻辑模型结构均有效，但只有 27 个完成 model-specific contract，65 个仍 pending；模型 exact gate 保持 blocked。
2. 本轮浏览器检查证明当前页面可用且状态闭环，但尚未为当前 frontend build 重录完整 UI 像素证据和 Browser 10/10 合同；主效果 canonical 报告也仍有 9 个失败，不能用人工截图或功能测试替代正式 exact 门禁。

多图工作流的必需阻断已在最终复跑中关闭：全景由错误的整图缩放改为保留像素几何的原生有效边界裁切，MAE 从 `0.081941` 降至 `0.013422`，SSIM 从 `0.815541` 提升至 `0.994115`；HDR、焦点堆栈、全景均已通过。

## 2. 已完成实现

### 2.1 目录与右键交互

- 目录默认选中“所有照片”，当前实测显示 21 张，主网格拥有独立纵向滚动容器。
- 目录、文件夹和多图工作流保持同一工作区壳层；计数来自统一 catalog 状态，不再因进入工作流而归零。
- 照片右键菜单包含标记、评分、旋转、浏览、合并、调整、导出、转到、回收站和直方图入口。
- 文件夹右键菜单包含打开和导入到当前文件夹；没有真实数据模型支撑的重命名、永久删除等操作明确禁用。
- 收藏、拒绝、评分、旋转和回收站写入后端目录记录；旋转同步到预览与项目渲染。
- 原产品范围验证器原先错误禁止评分和收藏；依据本机右键采样已更新范围规则，重新验证通过。

### 2.2 编辑器与裁切

- 工具点击采用原生内联展开，不再跳转到独立编辑页。
- 每张照片拥有独立编辑历史；无编辑时显示“没有编辑”，有编辑时显示对应效果与参数。
- 裁切工具提供比例、构图、水平校正、旋转、水平/垂直翻转和应用；画布提供九宫格、遮罩、移动框和四角拖拽。
- 固定比例根据源图宽高约束裁切框。应用裁切时先调用显著性 ONNX/IR 模型，再执行用户确认的裁切和变换；测试确认模型被调用且输出尺寸真实改变。
- 裁切叠层只在“工具 → 裁切”展开时显示，切换预设、编辑、更多或信息后不再残留。

### 2.3 图层、遮罩和素材

- 图层区保持原生窄栏、居中的添加入口、图层顺序、显隐、删除与原图层。
- 图层属性包含透明度、混合模式、缩放、位移、旋转、翻转和遮罩页。
- 遮罩支持导入、预览、反转、密度、羽化、删除、撤销与重做。
- 内置图层素材来自本地 Luminar 素材清单；“添加本地素材”直接导入图像，不再跳转升级弹窗。

### 2.4 预设、更多与信息

- 预设首页按风景、大自然、人像、创意分块，使用本地原生集合封面。
- 保留“添加”入口并导入本地 `.lnp`，删除已购买、商店和升级路径。
- 更多页使用原生增强/合并卡片；提升分辨率和修复进入真实能力，HDR、焦点堆栈和全景进入真实多图工作流。
- 影像资讯页对齐原生元数据卡，显示文件名、日期、相机、镜头、尺寸、文件大小、ISO、焦距、EV、光圈和快门。
- 导入项目时立即写入源图尺寸和可用 EXIF；读取缺少事实字段的项目时补齐当前源图数据。

### 2.5 删除的旧逻辑

- 删除 `ApplicationDialog.tsx` 和对应测试。
- 删除 App 中升级/帮助弹窗状态及调用路径。
- 删除图层“获取更多资产 → 升级”行为，改为本地素材导入。
- 合并目录照片卡重复 CSS 定义，保留一套当前原生样式。

## 3. 模型与 SQLite 结论

- `configs/model.yaml`：`primary: onnxruntime`、`fallback: openvino`。
- `ModelRegistry.resolve` 对 ONNX/ORT 的优先级为 0，对 OpenVINO IR 为 1；只有 ONNX 不可用且 IR 被允许并通过文件/运行时验证时才回退。
- ONNX/OpenVINO 选择、IR 后端与三类工作流的 17 项专项测试通过。
- Portable 目录只找到 `profiles/crop.db` 和 `profiles/data.mlcdb`。`crop.db` 是 SQLite，只有 `cameras(id, brand_name, camera_name, crop_rect)`，共 800 行；`data.mlcdb` 是专有二进制，不是 SQLite。
- 未发现原生目录数据库及其表结构，因此本轮没有伪造“与 Luminar 相同”的 SQLite catalog schema。当前 JSON catalog 保持单一活动存储；拿到真实 schema 证据后再一次性迁移，不保留双写兼容层。
