## 2. 本轮完成的实现

### 2.1 恢复原始状态改为严格状态机

`scripts/luminar_capture/auto_sampler.py` 现在把 Luminar 菜单项 `ResetAllEdits` 作为原始状态的权威信号：

1. 每个采样用例开始前打开图片操作菜单；
2. 只要“恢复到原始状态”可用，就执行一次恢复；
3. 再次打开菜单复查；
4. 如果仍可用，继续恢复；
5. 只有该菜单项变为不可用，才允许进入效果应用阶段；
6. 记录 `reset_action_count`、最终禁用状态和输入文件/hash 证据。

因此，“点击过一次恢复”不再等于“已恢复完成”。同一图片残留多层编辑时会重复清除，直到 Luminar 自己报告没有可恢复编辑。

### 2.2 效果成功与导出改为事件驱动

旧流程同时依赖预览像素变化、稳定帧数量和固定等待。AI 效果、人物塑形或降噪可能已经改变完整导出，但低分辨率预览变化不稳定，从而被误判为失败并重试。

新流程采用以下顺序：

1. 应用正确的控件和参数；
2. 轮询“恢复到原始状态”是否变为可用；
3. 一旦可用，认定 Luminar 已建立编辑状态；
4. 只保留一帧导出前证据，立即进入导出；
5. 导出文件稳定后，使用原图与完整导出的变化指标做最终有效性审计；
6. 一旦 attempt journal 已存在 `exported` 事件，后续异常一律不可自动重试。

这直接修复了“身体效果视觉上已变化却重复导出”的问题：旧流程在导出后因预览一致性检查失败，把已完成任务重新执行；新流程在导出成功后终止任务。已有身体效果导出通过状态权威恢复发布为 canonical，没有再次操作 Luminar。

### 2.3 特殊交互约束

- 黑白：先点击“转换为黑白”，再采集亮度、饱和度等可用控制；
- 降噪：主用例参数为 `denoise_level=middle`，只激活 `NSButton.Noiseless.Mid`，不再把低、中、高当作同一用例的重试序列；
- LUT：先展开 `Cinematic Toning` 父菜单，再选择 `Anaheim`，并以编辑状态和 Amount 滑杆读回联合校验；
- Magic Light / New Neon Light：改用夜景固定输入；
- Slim People：改用适合人物塑形的输入；
- 模型推理：候选生成等待完整 inference result 和最终导出，不用预览或中间状态替代完成结果。

## 3. 重复导出根因与修复结果

### 3.1 根因

身体效果重复导出不是因为视觉没有变化，而是旧采样状态机的终止条件错误：

- Luminar 已应用人物塑形；
- “恢复到原始状态”已可用；
- 完整文件已经导出；
- 但导出后的低分辨率 preview consistency 不满足旧阈值；
- 异常仍被分类为可重试；
- 调度器重新应用同一效果并再次导出。

换言之，旧逻辑把“预览验证不稳定”错误提升成“导出未完成”。

### 3.2 修复

- `exported` 成为 attempt 的不可逆完成边界；
- 已导出后的异常变为 `NonRetryableCaptureError`；
- 状态权威恢复器可以验证既有导出的编辑状态和导出变化后直接发布 canonical；
- 主队列 dry-run 为 0 pending，不再重复采样；
- 重复原生导出 postcheck 为 0。

## 4. 性能对比

以同一 `sensor-noise` 降噪用例为可复核样本：

| 指标 | 执行前 | 执行后 | 变化 |
|---|---:|---:|---:|
| 单次 attempt 总耗时 | 345.824 秒，最终失败 | 23.508 秒，ready | 降低约 93.2% |
| 激活等级 | 依次尝试低/中/高 | 只选择语义匹配的中等 | 去除 2 次无意义激活 |
| 效果后等待 | 61–103 秒预览轮询 | 状态可用后进入导出 | 去除固定长等待 |
| 文件导出阶段 | 未产生有效终态 | 4.449 秒 | 有完整稳定文件 |
| canonical 发布 | 无 | 0.206 秒 | 原子发布 |

最新 LUT 用例在严格恢复一次、状态确认、一帧证据和文件导出全部完成后总耗时 25.190 秒，其中导出 4.504 秒、canonical 发布 0.116 秒。

恢复原图本身仍可能较慢：如果 Luminar 内部存在多层历史编辑或 AI 结果，必须重复执行恢复直到菜单禁用。这里不能用固定短暂停代替状态确认，否则会重新引入效果叠加。后续性能优化只能减少菜单查找、截图和重复打开面板的开销，不能跳过最终不可用确认。

1. 先处理接近阈值的 `face_ai`、`bw_channels`、`denoise`：固定当前 reference，不动采样，逐项校准强度曲线、色彩空间、掩膜和细节恢复；

### P3：修全景，不扩大多图架构

### P4：主效果稳定后再收敛 exact 31 项

使用 `convergence-failures-round-3-final.json` 按能力聚类。优先把主效果修复传播到 exact 同能力案例，再处理 vignette、grain、face_enhancer 等仅在 exact 集失败的能力。禁止调宽阈值或重新采样来掩盖候选算法差距。

### P5：保持“已采样不重复”的硬规则

只有以下情形允许重新采样 Luminar：

1. canonical 证据缺文件、hash 不匹配或数据链失败；
2. 审计确认导出与原图无有效变化；
3. Luminar 版本/build、输入 hash、参数、素材或交互语义发生变化；
4. 当前 reference 被人工判定为错误采样并登记 invalid reason。

候选效果失败、UI 失败或算法尚未对齐，都不构成重新采样理由。
